Executive Summary

This automation suite provides complete end-to-end sanity coverage for the Impetus Unified Vendor Portal (UVP), spanning both the ODM and OEM workflows across three roles — Buyer, Vendor, and Cluster — from inspiration upload through PO creation and sample dispatch.


Previously, a full sanity cycle required ~16 hours of manual effort across multiple testers logging in as different roles, creating data, and verifying each workflow step. With this automation, the same cycle now completes in ~1.5 hours with zero manual intervention — a ~10x speed improvement and significant reduction in human error.


The suite also incorporates visual validation (UI highlighting and automated screenshots), API-level verification (DP create, cookie-based auth), negative testing (duplicate packs, cost validation, submit-without-changes), and Allure reporting for pass/fail analytics.

Key Capabilities Covered

  • Login with session caching (single login reused across all tests for speed)
  • Workspace navigation and role switching (Buyer, Vendor, Cluster)
  • Inspiration upload (PDF + XLSX brick file) with theme creation and date picker
  • Cluster & Vendor Cluster association verification (UI highlighting + screenshots)
  • Design submission by vendor with article code, HSN code, brick name, colorways (5 colors), costing, and fabric composition
  • Multi-pack creation (MULTI-1 through MULTI-6) with colorway quantity combinations
  • Duplicate pack detection and cancellation
  • Comment system with text entry and file attachment
  • Cluster rework and approval workflows (multiple cycles)
  • Buyer rework, park, unpark, and re-park flows
  • Vendor rework with HSN code editing across multiple iterations
  • Edge case: Vendor submits without making changes (negative test)
  • Edge case: Colorway cost exceeding minimum pack cost validation
  • Edge case: Updating colorway cost and SAP color ID changes
  • Edge case: Invalid SAP color ID (MULTI4 does not exist) error validation
  • Buyer approval with size group selection, colorway approvals, and pack approvals
  • Design rejection with reason selection (Colors Not Suitable)
  • FPT & GPT approval flow
  • DP (Development Pack) creation via API call with cookie authentication
  • PP Sample lifecycle (submit, resubmit, buyer approve, cluster approve)
  • Vendor Cluster filter on Submitted Design listing
  • Email Submitted Design Data trigger (triggered from UI; email content verified manually via Gmail)
  • Sample Dispatch page verification (PO Number, Style ID, Vendor Style Codes, PO Issue Date)
  • Full OEM flow: buyer design upload, sharing, vendor submission, cluster approval, rework cycles
  • OEM bulk upload and auto-reject scenarios
  • Bell notification and email notification verification (emails triggered from UI; email content verified manually via Gmail)
  • Automated Allure reporting with failure screenshots, error attachments, and PDF generation
